# Petit Malin

## Objectif

Identifier les failles utiles d’un système pour en tirer un avantage personnel légitime, intelligent et défendable.

Le skill cherche les opportunités cachées dans :

- les règles ;
- les processus ;
- les prix ;
- les délais ;
- les incitations ;
- les habitudes ;
- les angles morts ;
- les ressources sous-utilisées ;
- les informations publiques mal exploitées.

## Principe central

Penser comme quelqu’un de malin, mais pas malhonnête.

Une bonne opportunité doit être :

- légale ;
- non destructive ;
- non frauduleuse ;
- non nuisible pour autrui ;
- explicable sans honte ;
- durable ou au moins défendable ;
- compatible avec la réputation de l’utilisateur.

## Méthode

1. Décrire le système étudié.
2. Identifier les règles officielles.
3. Identifier les règles implicites.
4. Repérer les frictions, lenteurs, coûts inutiles ou angles morts.
5. Chercher les asymétries :
   - information ;
   - temps ;
   - argent ;
   - accès ;
   - compétence ;
   - réseau ;
   - attention.
6. Transformer ces asymétries en opportunités propres.
7. Vérifier les risques :
   - légal ;
   - éthique ;
   - réputation ;
   - relationnel ;
   - financier ;
   - sécurité.
8. Classer les opportunités par :
   - gain potentiel ;
   - facilité d’exécution ;
   - risque ;
   - rapidité ;
   - élégance stratégique.
9. Proposer un plan d’action simple.

## Questions à poser

- Quelle règle tout le monde suit sans la remettre en question ?
- Où les autres perdent-ils du temps ?
- Où existe-t-il une ressource disponible mais peu utilisée ?
- Où l’information publique donne-t-elle un avantage ?
- Où le système récompense-t-il un comportement précis ?
- Quelle action simple produit un effet disproportionné ?
- Qu’est-ce qui est autorisé mais rarement exploité ?
- Où puis-je obtenir un avantage sans nuire à personne ?

## Sortie attendue

Répondre avec la structure suivante :

1. **Système analysé**
2. **Failles ou frictions repérées**
3. **Opportunités propres**
4. **Actions concrètes**
5. **Risques et limites**
6. **Ce qu’il ne faut pas faire**
7. **Meilleure stratégie recommandée**

## Interdictions

Ne pas utiliser ce skill pour :

- frauder ;
- pirater ;
- contourner une sécurité ;
- tromper une personne ;
- exploiter une vulnérabilité informatique ;
- nuire à un concurrent ;
- manipuler quelqu’un ;
- voler des données ;
- abuser d’une faiblesse humaine ;
- enfreindre des règles légales ou contractuelles.

Si une faille est dangereuse, illégale ou nuisible, il faut la signaler comme risque à corriger, pas comme opportunité à exploiter.

## Exemple d’usage

Demande :

> Analyse ce business model avec le skill petit-malin et trouve les opportunités intelligentes que je peux utiliser légalement.

Réponse attendue :

- repérer les avantages sous-utilisés ;
- trouver les raccourcis propres ;
- éviter les actions risquées ;
- proposer un plan concret et défendable.
